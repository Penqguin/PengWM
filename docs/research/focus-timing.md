## 1. Question and domain constraints

**Question.** Would a small focus-timing module deepen the existing state interface by concentrating quiet-window, explicit-switch, and fallback-memory decisions, without duplicating workspace membership or display assignment?

The existing ownership constraints are substantial:

- Membership stays on `Workspace`; durable routing verdict stays in `WindowStore`. A focus refactor must ask those owners instead of inventing a per-window focus membership record. [ADR-0003](../adr/0003-window-identity.md#L21)
- `DisplaySet` owns visible assignments, focused output, and routing policy; `StateManager` retains the workspace pool and executes hide/layout/publication. [Architecture](../architecture.md#L140)
- Topology changes reseat and relayout without re-homing members; automatic topology repair must not become focus-triggered reset/rebirth. [ADR-0006](../adr/0006-topology-never-rehomes-members.md#L34)
- Native-Space limbo freezes actions on the affected display while retaining model bookkeeping. It is not a blanket prohibition on focus bookkeeping. [ADR-0007](../adr/0007-native-space-gate.md#L27)
- Explicit workspace selection carries traveling overflow; ordinary monitor focus leaves it on its monitor. A focus-timing change must preserve that distinction. [ADR-0008](../adr/0008-current-workspace-overflow.md#L5), [placement spec](../specs/0003-window-placement.md#L19)

**Historical evidence.** The changelog records the stale-last click storm, 250 ms quiet re-read, fallback ladder, and settle-only last-window memory; it separately records why explicit focused output must precede the PID heuristic. The corresponding source-history commits are `b8fd6e4` and `cf02db1` (`git show` inspected during this review). [Focus history](../../CHANGELOG.md#L54), [workspace-resolution history](../../CHANGELOG.md#L81)

The current paths are:

1. AX focused-window notification → `DaemonEvent::WindowFocused` → event-loop dispatch → `on_window_focused_event` → dirty timestamp + immediate `on_window_focused`. [Observer](../../pengwm-daemon/src/macos/ax_observer.rs#L665), [dispatch](../../pengwm-daemon/src/event_loop.rs#L156), [arrival interface](../../pengwm-daemon/src/state/lifecycle.rs#L774)
2. `AppActivated` → update frontmost PID → discover missed windows for that PID → ask its OS-focused window → immediate acceptance, or publication if absent. This path does **not** arm the quiet-window drain itself. [Dispatch](../../pengwm-daemon/src/event_loop.rs#L167), [activation](../../pengwm-daemon/src/state/lifecycle.rs#L759)
3. The run loop drains queued events before ticking. Tick samples `now`, refreshes the native-Space gate, drives wake resync, then runs settled focus. A quiet threshold is therefore eligibility on the next tick, not an independent timer callback with a guaranteed 250 ms deadline. [Pump](../../pengwm-daemon/src/event_loop.rs#L120), [tick ordering](../../pengwm-daemon/src/state/reconcile.rs#L22)
4. Settled focus → wake judgment permission → 250 ms quiet check → consume dirty → explicit-switch deadline check → adapter frontmost PID and focused-window read → immediate acceptance or visible-last-window fallback or leave seat alone. [Implementation](../../pengwm-daemon/src/state/lifecycle.rs#L799), [constant](../../pengwm-daemon/src/state/mod.rs#L214)
5. Commands retain their own focus selection and actuation: directional focus and cycling update workspace focus and call the adapter; workspace switches plan, carry overflow, hide/layout/focus/stack, then install the deadline; display focus updates the output even if empty. These paths do not assign settled last-window memory directly. [Focus/cycle](../../pengwm-daemon/src/state/commands.rs#L34), [directional focus](../../pengwm-daemon/src/state/commands.rs#L250), [switch](../../pengwm-daemon/src/state/commands.rs#L79), [display focus](../../pengwm-daemon/src/state/commands.rs#L340), [settled memory assignment](../../pengwm-daemon/src/state/lifecycle.rs#L824)

**Important distinction:** immediate acceptance ignores parked windows, probes native fullscreen, and ignores members on hidden workspaces. For a visible member, it changes workspace focus **before** checking switch debounce; that deadline suppresses only the subsequent focused-output change, while still publishing bar state. There is no active-seat mutation in this path. The field and older comments that describe suppressing `DisplaySet::active` mutation are stale descriptions of the current implementation. [Immediate acceptance](../../pengwm-daemon/src/state/lifecycle.rs#L344), [stale field comment](../../pengwm-daemon/src/state/mod.rs#L111)

## 3. Evidence: temporal decisions and lifecycle interactions

| Situation | Current decision and retained state |
|---|---|
| Focused event at `t` | Replace dirty timestamp with `t`; attempt immediate acceptance. A later event restarts the quiet window. [Arrival](../../pengwm-daemon/src/state/lifecycle.rs#L779) |
| No dirty timestamp | Settled drain returns without querying OS. [Drain](../../pengwm-daemon/src/state/lifecycle.rs#L799) |
| Wake resync pending | Settled drain returns with dirty timestamp retained, regardless of its age. Immediate acceptance is not gated by this settle-specific check. [Drain](../../pengwm-daemon/src/state/lifecycle.rs#L803), [judgment gate](../../pengwm-daemon/src/state/blackout.rs#L170), [immediate path](../../pengwm-daemon/src/state/lifecycle.rs#L344) |
| Quiet age < 250 ms | Leave dirty armed; no settled OS read. At exactly 250 ms the `<` comparison permits the drain. [Quiet check](../../pengwm-daemon/src/state/lifecycle.rs#L807) |
| Quiet age ≥ 250 ms, `now < switch_until` | Consume dirty, then return without refreshing frontmost PID or last-window memory. At equality the deadline permits the read. [Ordering](../../pengwm-daemon/src/state/lifecycle.rs#L810) |
| Due and switch deadline passed | Read frontmost PID; store it even if absent; query its focused window, then use the ladder. Settled drain does not clear an expired switch deadline itself. [Read/ladder](../../pengwm-daemon/src/state/lifecycle.rs#L813) |
| Visible immediate candidate within deadline | Workspace focus changes; bar publishes; output focus stays as it was. [Ordering](../../pengwm-daemon/src/state/lifecycle.rs#L379) |
| OS `None`, last window still visible | Attempt immediate acceptance of remembered window; no workspace reveal or switch. Otherwise leave seat alone. [Fallback](../../pengwm-daemon/src/state/lifecycle.rs#L829) |
| Wake commits in tick | Wake refreshes frontmost PID; settled drain follows in that same tick and can consume a previously due timestamp. [Wake read](../../pengwm-daemon/src/state/blackout.rs#L271), [tick ordering](../../pengwm-daemon/src/state/reconcile.rs#L30) |
| Structural reset | Replace workspaces/DisplaySet/store; clear switch deadline and drag state. Dirty timestamp, remembered window and frontmost PID are not explicitly cleared in reset. [Reset](../../pengwm-daemon/src/state/reset.rs#L98), [timer tail](../../pengwm-daemon/src/state/reset.rs#L127) |
| Native-Space change | Force gate refresh; entering limbo clears drag; return resyncs layout/hides/stacking. This path does not clear/arm focus timing. Immediate focus bookkeeping has no separate limbo guard. [Space transitions](../../pengwm-daemon/src/state/space_gate.rs#L88), [return](../../pengwm-daemon/src/state/space_gate.rs#L160), [notification](../../pengwm-daemon/src/state/space_gate.rs#L240), [focus](../../pengwm-daemon/src/state/lifecycle.rs#L344) |

**Reachability inference, not a demonstrated defect.** A focus arrival and switch at the same instant cannot by themselves hit the consume-before-switch-return branch: focus matures at +250 ms and switch protection ends at +150 ms. A *later* switch can overlap an older dirty timestamp: for example, arrival at `t=0`, switch at `t=200 ms`, and a tick at `t=250 ms` satisfies quiet age ≥250 and switch deadline `350 ms` > now. The queue accepts commands between focused events and the next tick, so that event ordering is structurally possible. However, an intervening focused event would re-arm quiet and change the timeline; this review has not observed the necessary OS notification sequence live. Whether discarding that old observation is intentional switch authority or lost work is a product decision, not proven wrong by statement order. [Threshold](../../pengwm-daemon/src/state/mod.rs#L214), [deadline installation](../../pengwm-daemon/src/state/commands.rs#L124), [queue/tick ordering](../../pengwm-daemon/src/event_loop.rs#L123), [consumption](../../pengwm-daemon/src/state/lifecycle.rs#L810)

**Time consistency inference.** `commit_settled_focus(now)` uses the supplied instant for eligibility, then calls `on_window_focused`, which reads real `Instant::now()` for its deadline. A deterministic test cannot safely advance only the former and assume both decisions use that time. Prefer carrying one decision instant through both paths if this candidate is implemented; production wrappers should sample real time once. No clock adapter is needed to solve this discrepancy. [Supplied time](../../pengwm-daemon/src/state/lifecycle.rs#L799), [second sample](../../pengwm-daemon/src/state/lifecycle.rs#L385), [nested acceptance](../../pengwm-daemon/src/state/lifecycle.rs#L827)

## 5. Candidate seam, deletion test, and two real adapters

**Recommendation / inference:** concentrate the temporal state and decisions in one focus-timing module, initially owning quiet arrival, switch protection and settled last-window memory. Consider frontmost PID part of that module only if activation, constructor and wake refresh all use the same small interface; moving its field while leaving those writes distributed buys little locality. Keep `focused_output` in `DisplaySet`, since it participates directly in planner, bootstrap, topology repair and active-seat resolution. [Existing temporal cluster](../../pengwm-daemon/src/state/lifecycle.rs#L774), [PID writes](../../pengwm-daemon/src/state/blackout.rs#L271), [DisplaySet planner](../../pengwm-daemon/src/state/display.rs#L191), [DisplaySet resolution](../../pengwm-daemon/src/state/display.rs#L282), [topology repair](../../pengwm-daemon/src/state/display.rs#L515)

The interface should hide quiet re-arming, switch precedence, and remembered-window progression rather than expose field setters. Leave membership with `Workspace`, identity/parking with `WindowStore`, output assignment with `DisplaySet`, command destination/overflow/OS requests with commands, wake/Space permissions with their existing modules, and scheduling with the event loop. This preserves the owners established above. [Acceptance dependencies](../../pengwm-daemon/src/state/lifecycle.rs#L344), [command execution](../../pengwm-daemon/src/state/commands.rs#L79), [judgment gate](../../pengwm-daemon/src/state/blackout.rs#L170), [Space policy](../../pengwm-daemon/src/state/space_gate.rs#L111), [scheduling](../../pengwm-daemon/src/event_loop.rs#L120)

**Deletion test / inference:** deleting a useful timing module should force quiet re-arming, wake-versus-switch retention ordering, deadline comparison, and settled-memory progression back into arrival, tick and command/reset callers. If deletion merely restores renamed setters around the same scattered conditions, the extraction was shallow. This proposed leverage follows from the currently separate writes and decisions, not from a need for another trait. [Arrival/drain](../../pengwm-daemon/src/state/lifecycle.rs#L774), [command deadline](../../pengwm-daemon/src/state/commands.rs#L124), [reset deadline](../../pengwm-daemon/src/state/reset.rs#L127)

**Two real adapters already exist at the dependency seam:** `MacOsAdapter` delegates frontmost/focused reads to macOS AX helpers and resolves an element for focus actuation; `TestAdapter` answers from cells/maps and records focus requests, with `SharedTestAdapter` forwarding the same trait for handle-based tests. Reuse this real seam; the proposed timing module is ordinary policy, not a second pair of production/test adapters or a reason for a new focus-only trait. [Production reads](../../pengwm-daemon/src/adapter_macos.rs#L574), [production actuation](../../pengwm-daemon/src/adapter_macos.rs#L769), [test reads](../../pengwm-daemon/src/adapter_test.rs#L715), [test actuation](../../pengwm-daemon/src/adapter_test.rs#L829), [shared forwarding](../../pengwm-daemon/src/adapter_test.rs#L586)

## 6. Minimal migration and test strategy — proposed, not implemented

1. Agree on the unresolved semantics below. First pin current observable order through existing state/adapter tests; do not “fix” consume-before-switch or remembered-window acceptance implicitly. Existing tests already use shared adapter injection for independent OS truth. [Harness](../../pengwm-daemon/src/state/tests/common.rs#L58), [truth injection](../../pengwm-daemon/src/adapter_test.rs#L960)
2. Introduce an explicit-time internal path, with production event/tick wrappers reading time once and forwarding that same instant through eligibility and acceptance. Reuse `commit_settled_focus(now)` and existing `TestHandle`; add no clock trait, dependency, downcast, or second OS interface. [Existing time seam](../../pengwm-daemon/src/state/lifecycle.rs#L799), [current second clock read](../../pengwm-daemon/src/state/lifecycle.rs#L385), [adapter harness](../../pengwm-daemon/src/state/tests/common.rs#L58)
3. Move only agreed temporal state and decision order into the module; route arrival, settled drain, successful switch and reset through it. Keep existing acceptance effects and owners visible until an alternative interface proves smaller. Characterize reset's retained dirty/last-window lifetime before any change to it. [Current sites](../../pengwm-daemon/src/state/lifecycle.rs#L774), [switch site](../../pengwm-daemon/src/state/commands.rs#L124), [reset site](../../pengwm-daemon/src/state/reset.rs#L127)
4. Replace timing sleeps in the focus scenarios with explicit decision instants through the same interface callers use; retain event/tick and real-macOS integration checks for scheduling and actual focus. Pure timing tests cannot prove AX ordering or actual focus. The repository explicitly requires interactive macOS validation for real window-management changes. [Current sleeps](../../pengwm-daemon/src/state/tests/focus.rs#L12), [tick scheduler](../../pengwm-daemon/src/event_loop.rs#L123), [repository verification rule](../../AGENTS.md#L21)

Suggested deterministic scenarios: quiet 249/250 ms and re-arm; switch 149/150 ms; same-arrival switch versus older-dirty/newer-switch; repeated switches; visible second-output candidate during protection; hidden/parked/unknown OS candidates; no OS focus with visible/hidden/destroyed remembered member; activation without a focused event; wake retention and same-tick recovery; reset while dirty; native-Space bookkeeping versus gated requests. These are **proposed coverage**, derived from the decision table, not asserted failures. [Current gates](../../pengwm-daemon/src/state/lifecycle.rs#L344), [drain](../../pengwm-daemon/src/state/lifecycle.rs#L799), [reset](../../pengwm-daemon/src/state/reset.rs#L98), [Space contract](../adr/0007-native-space-gate.md#L27)

**Tradeoffs / inference:** a timing-only module is the smallest migration and keeps ownership stable, but may remain shallow if callers still encode the important ordering. Moving acceptance as well can concentrate more behavior, at the cost of borrowing workspace/store/display state and fullscreen/publication effects. A full focus coordinator risks absorbing unrelated ownership and replacing a small temporal problem with a broad interface. Choose the smallest interface that hides the temporal decisions while leaving membership, placement and actuation with their existing owners. [Acceptance dependencies](../../pengwm-daemon/src/state/lifecycle.rs#L344), [temporal decisions](../../pengwm-daemon/src/state/lifecycle.rs#L799), [ownership constraints](../adr/0003-window-identity.md#L21)

## 7. Concrete decisions for user discussion

1. **What does “last focused window” mean?** Preserve last OS-reported window, as implemented, or remember only an accepted visible member? Decide separately whether rejected OS `Some` should invoke the fallback ladder. [Current order](../../pengwm-daemon/src/state/lifecycle.rs#L824)
2. **What does switch protection protect?** Preserve today's workspace-focus update while holding output focus, and consume older due dirty work during a newer switch, or retain/re-sample it afterward? Ordinary hidden-workspace rejection already has a separate permanent visibility rule. [Immediate order](../../pengwm-daemon/src/state/lifecycle.rs#L371), [settled order](../../pengwm-daemon/src/state/lifecycle.rs#L810)
3. **Which inputs promise later correction?** Only external `WindowFocused`, as now, or activation and explicit commands too? Expanding arming is a behavior change and may affect switch authority. [Arming](../../pengwm-daemon/src/state/lifecycle.rs#L779), [activation](../../pengwm-daemon/src/state/lifecycle.rs#L759), [command focus](../../pengwm-daemon/src/state/commands.rs#L34)
4. **What survives structural reset?** Preserve armed quiet work and remembered focus across replacement of the workspace/store world, or discard/validate them explicitly? Automatic topology healing remains outside reset regardless. [Reset](../../pengwm-daemon/src/state/reset.rs#L98), [ADR-0006](../adr/0006-topology-never-rehomes-members.md#L34)
5. **How broad should the module be?** Timing only, or timing plus immediate acceptance orchestration? Keep focused-output ownership with `DisplaySet` unless a separate architecture decision changes its planning interface. [Current planner ownership](../architecture.md#L140), [acceptance implementation](../../pengwm-daemon/src/state/lifecycle.rs#L344)

No additional decision to freeze focus bookkeeping in native-Space limbo is implied by this review: the accepted ADR intentionally distinguishes actions from model bookkeeping. Any such change would need its own stated requirement. [ADR-0007](../adr/0007-native-space-gate.md#L27)
